# ADR-0003 실시간 동기화보다 주 1회 Import 최적화

- 날짜: 2026-08-05
- 관련 결정: [ADR-0001 파일 Import](ADR-0001-file-import-over-financial-api.md), [ADR-0002 local-first](ADR-0002-local-first-architecture.md)

## 상태

Accepted

## 최초 사용자 요구

금융 거래를 자동으로 가져와 수기 가계부 작성을 없애고자 했다.

## 이후 대화에서 확인된 문제

자동화라는 표현이 실시간 수집을 반드시 뜻하지는 않는다. 사용자는 매 순간 잔액을 확인하기보다 주말에 일주일치 소비를 한 번 정리하는 방식을 원한다.

## 변경된 요구사항

상시 연결과 백그라운드 동기화 대신, 주 1회 사용자가 시작하고 완료하는 짧고 신뢰할 수 있는 Import·검토 흐름을 제공한다.

## 결정

초기 UX와 성능 목표는 일주일치 데이터를 한 번에 가져와 분류 결과와 중복 후보를 검토하는 작업에 맞춘다. 실시간 알림, 예약 동기화, 백그라운드 작업은 구현하지 않는다.

## 결정 이유

- 사용자의 실제 관리 습관과 일치한다.
- 실시간 인프라 없이도 반복 수기 입력을 크게 줄일 수 있다.
- 사용자가 자동 분류 결과를 한 자리에서 확인할 수 있다.

## 고려한 대안

### 실시간 또는 일 단위 자동 동기화

최신성은 높지만 현재 사용자 가치에 비해 인증, 네트워크, 오류 복구 비용이 크다.

### 월 1회 정리

빈도는 낮지만 확인할 거래가 지나치게 누적되고 생활비 초과를 늦게 알 수 있다.

## 장점

- 사용 흐름과 구현 범위가 명확하다.
- 자동 판정 오류를 사용자가 정기적으로 검토할 수 있다.
- 주간 생활비 피드백과 자연스럽게 연결된다.

## 단점

- Dashboard가 마지막 Import 이후 거래를 반영하지 못한다.
- 사용자가 주간 작업을 잊으면 데이터가 누적된다.

## 향후 다시 검토할 조건

- 사용자가 주 1회 작업을 지속적으로 놓친다.
- 최신 잔액이나 이상 거래 알림이 핵심 요구가 된다.
- 안전하고 공식적인 자동 데이터 연결 수단이 확보된다.
