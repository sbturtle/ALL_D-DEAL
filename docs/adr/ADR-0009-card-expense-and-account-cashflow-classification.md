# ADR-0009 — 카드 사용은 소비, 계좌 거래는 현금흐름으로 먼저 분류한다

- Status: Accepted
- Date: 2026-08-05

## Context

같은 소비가 카드 이용내역에는 구매 시점의 지출로, 계좌 거래내역에는 카드대금 출금으로 나타난다. 계좌 설명에는 저축·대출상환·이체·리워드·수입도 함께 섞여 있어 이를 일반 지출이나 카테고리로 먼저 처리하면 생활비와 현금흐름이 왜곡될 수 있다.

현재 Importer는 카드와 계좌의 안전한 공통 필드를 Preview로 정규화하고, 생활비는 `EXPENSE + OUTFLOW`만 집계한다. 개인 금융 식별자와 원본 행은 local-only Preview에서도 보존하지 않는다.

## Decision

카드 이용내역을 소비 지출의 우선 출처로 유지한다. 계좌 거래는 카테고리 처리 전에 작은 코드 기반 규칙 엔진으로 거래 유형을 분류한다. 첫 규칙은 방향과 거래 설명의 명시적 표식만 사용하고, Preview에 `type`, 비식별 근거 코드, 확신 수준을 제공한다.

계좌 `CARD_PAYMENT`는 소비 카테고리가 아니라 현금흐름 유형이다. 따라서 생활비·소비 합계에는 포함하지 않는다. 카테고리 규칙과 카테고리 선택은 새 `EXPENSE` Preview 후보에만 적용한다.

`SELF_TRANSFER`는 본인 계좌 별칭이라는 사용자 설정이 있어야 확정할 수 있다. 이 설정이 없는 동안에는 일반 이체 또는 미분류 검토 상태로 둔다. 규칙 엔진은 범용 DSL이나 원격 서비스가 아닌, 테스트 가능한 작은 코드 모듈로 유지한다.

## Consequences

- 카드대금 출금이 카드 구매 지출과 이중 집계되지 않는다.
- 분류 규칙의 결과와 근거를 Import 시점에 검토할 수 있지만, 근거 메타데이터와 원본 행은 저장하지 않는다.
- 기존에 저장된 카테고리 데이터는 마이그레이션하거나 무효화하지 않는다. 새 Preview부터 유형 우선 규칙을 적용한다.
- 개인 계좌 별칭, 이체 상호대조, 상호/브랜드 정규화, 사용자 분류 규칙 관리, Kakao 등 외부 API 연동은 별도 요구사항과 보안 설계 후에만 추가한다.
