# ADR-0016 — 널리 알려진 상호에 내장 기본 카테고리 추천을 Preview에만 적용한다

- 상태: 채택
- 날짜: 2026-09-29
- 관련: [ADR-0007](ADR-0007-confirmed-description-category-rules.md)을 보완한다

## 최초 사용자 요구

ADR-0007은 사용자가 명시적으로 동의한 설명·키워드 규칙만 Preview 카테고리를 채우고, Import 시 자동 추론은 채택하지 않았다.

## 이후 확인된 문제

배포 사이트 점검에서 카드 XLS 81건이 모두 `미분류`로 나왔다. 스타벅스, 버거킹, CGV, 쿠팡, 편의점처럼 누가 봐도 분명한 상호도 사용자가 한 건씩 골라야 했고, Home에는 `분류가 필요한 거래 80건`이 떴다. Kakao 장소 분석은 환경 설정이 없으면 동작하지 않아 대체 수단이 되지 못했다.

## 결정

1. `DEFAULT_CATEGORY_KEYWORDS`에 널리 알려진 브랜드와 업종 표식(카페, 편의점, 패스트푸드·배달, 영화·서점, 쇼핑몰, 구독, 교통, 의료 등)을 코드 상수로 둔다.
2. 적용 순서는 사용자 정확 규칙 → 사용자 키워드 규칙 → 내장 기본 추천 → Kakao 분석이다. 기본 추천은 사용자 규칙이 없는 `EXPENSE` 후보에만 적용한다.
3. 비교는 기존 키워드 정규화와 같은 포함 비교이며, 가장 긴 키워드가 우선한다(`쿠팡이츠` > `쿠팡`, `이마트24` > `이마트`). `CU`, `KT`처럼 다른 단어에 쉽게 포함되는 짧은 영문 약어는 제외한다.
4. 기본 추천은 Preview에서만 카테고리를 채우고 후보에 `categorySource: 'DEFAULT_KEYWORD'`를 붙인다. 화면에는 `기본 추천`으로 표시해 사용자 규칙과 구분한다. 사용자는 저장 전에 언제든 바꿀 수 있다.
5. 기본 추천은 `CategoryRule`이나 `KeywordCategoryRule`을 만들지 않고, 이미 저장된 거래도 바꾸지 않는다. 규칙 저장은 기존처럼 사용자가 별도로 체크한 경우에만 한다.

## 2026-09-29 보완 — 범위 확장과 결제대행 대체 추천

재점검에서 45건이 여전히 미분류였다(G마켓, 무신사, 네이버페이, 구글플레이, 이니시스, 다이소, 노래연습장, 마라탕·칼국수 등). 다음을 추가했다.

- 오픈마켓·패션·생활용품 영문 표기(`g마켓`, `musinsa`, `daiso` 등), 앱 마켓·소프트웨어 구독(`구글플레이`, `앱스토어`, `google`, `microsoft` 등), 노래연습장·만화카페 같은 여가 업종, 스터디카페 같은 교육 업종을 넣었다.
- 마라탕·칼국수·냉면·돈까스·초밥·삼겹살·호프처럼 상호에 자주 들어가는 음식 업종어를 식비·외식 추천으로 넣었다.
- 네이버페이·카카오페이·토스페이·이니시스·KCP·다날·PAYCO 같은 결제대행 표식은 실제 상호를 숨기지만 대부분 온라인 구매라 `PAYMENT_INTERMEDIARY_FALLBACK_KEYWORDS`로 쇼핑을 추천한다. 설명에 실제 상호 키워드가 함께 있으면 그 상호가 우선하도록 일반 키워드 비교가 모두 실패했을 때만 사용한다. Kakao 분석에서 결제대행을 제외하는 기존 경계는 바꾸지 않는다.

업종어는 브랜드보다 오분류 가능성이 크지만 저장 전 수정할 수 있는 추천이고, 가장 긴 키워드 우선 규칙으로 `만화카페`(여가)·`스터디카페`(교육)가 `카페`보다 먼저 맞는다.

## 결정 이유

- 분명한 상호만 채워도 분류 작업량이 크게 줄고, 사용자는 남은 애매한 거래에 집중할 수 있다.
- 목록이 코드에 고정되어 있어 결과를 설명하고 테스트할 수 있으며, 외부 서버나 AI 없이 local-first 경계를 지킨다.
- 추천 출처를 표시하고 저장 전 수정 가능성을 유지해 ADR-0007이 막으려 한 “설명할 수 없는 자동 분류”를 피한다.

## 고려한 대안

- Kakao 분석만 사용: 환경 설정이 필요하고 상호명을 외부로 보내므로 기본값이 될 수 없다.
- 사용자에게 첫 실행 때 규칙을 만들게 하기: 초기 부담이 그대로 남는다.
- 기존 저장 거래까지 기본 추천으로 재분류: 과거 원장을 사용자 확인 없이 바꾸므로 채택하지 않았다.

## 장점과 단점

- 장점: 첫 Import부터 체감되는 자동 분류, 오프라인 동작, 테스트 가능한 결정 규칙.
- 단점: 포함 비교라 드물게 오분류가 생길 수 있다(예: 설명에 `카페`가 들어간 다른 업종). 목록은 코드 배포로만 바뀐다.

## 향후 다시 검토할 조건

- 오분류 사례가 반복되면 해당 키워드를 빼거나 접두 일치로 좁힌다.
- 사용자 규칙 관리 화면이 생기면 기본 추천을 끄는 설정과 이미 저장된 미분류 거래에 추천을 제안하는 검토 흐름을 함께 검토한다.
