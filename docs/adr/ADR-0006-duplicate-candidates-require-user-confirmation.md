# ADR-0006 — 중복 후보는 사용자 확인 후에만 저장한다

- Status: Accepted
- Date: 2026-08-05

## Context

반복 Import, 카드 이용 내역과 계좌 거래 내역의 중복, 같은 파일 안의 반복 행은 실제 생활비와 잔액 분석을 왜곡할 수 있다. 그러나 날짜와 금액, 설명이 같아도 실제로는 별개 결제일 수 있으며, 가져오기 형식의 해석 차이와 해시 충돌도 가능하다. 따라서 중복 신호만으로 저장된 거래를 삭제하거나 수정할 수 없다.

## Decision

Phase 4는 `occurredOn`, `amountMinor`, `currency`, `direction`, `type`, 정규화한 `descriptionOriginal`로부터 v1 비교 지문을 메모리에서 계산한다. 저장 거래 또는 같은 Preview의 앞선 후보와 지문이 같으면 **중복 가능성**으로만 표시한다.

중복 가능 후보는 기본적으로 저장 선택에서 제외한다. 사용자는 후보별 체크 또는 전체 재포함 동작으로 명시적으로 포함할 수 있다. 확정 시 선택된 후보만 저장하고, 제외 수는 `ImportBatch.skippedCount`에 기록한다. 기존 거래를 자동 삭제·병합·대체·수정하지 않는다.

지문과 정규화 문자열은 이 단계에서 IndexedDB에 저장하지 않으며, 저장소 스키마는 v1을 유지한다.

## Consequences

- 사용자는 저장 전 중복 가능성을 검토하고 최종 결정을 통제한다.
- 완전히 같은 입력을 다시 가져오는 실수를 줄이되, 정상적인 같은 날 반복 결제를 다시 포함할 수 있다.
- 현재 저장 거래 전체를 메모리에서 비교하므로 매우 큰 로컬 데이터셋에서는 성능 검토가 필요하다.
- 이 지문은 암호화나 동일 거래의 증명이 아니며, 향후 퍼지 매칭·영속 인덱스는 별도 ADR과 마이그레이션으로 다룬다.

## Alternatives considered

- 자동 삭제 또는 병합: 잘못된 삭제가 회복하기 어려워 채택하지 않았다.
- 지문을 즉시 영속화: 민감한 설명의 파생 데이터를 추가하고 스키마 마이그레이션을 요구하므로 현 단계에서는 보류했다.
- 금액·날짜 근접 퍼지 매칭: 거짓 양성 가능성이 커서 실제 사용 검증 뒤 별도 기능으로 검토한다.
