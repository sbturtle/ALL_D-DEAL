# ADR-0007 — 확정한 거래 설명 카테고리 규칙만 재사용한다

- Status: Accepted
- Date: 2026-08-05

## Context

현재 Legacy XLS Importer는 상호를 별도 필드로 안정적으로 제공하지 않고 거래 설명만 제공한다. 자동 카테고리는 생활비 분석에 유용하지만, 설명이 같아도 상황에 따라 다른 소비일 수 있고, 잘못된 분류를 소급 적용하면 원장을 왜곡한다.

## Decision

Phase 5는 정규화한 `descriptionOriginal`의 정확 일치를 규칙 키로 사용한다. 처음에는 식비·교통·주거/공과금·쇼핑·건강·교육·여가·구독·기타의 고정 카테고리만 제공하고, 카테고리가 없는 거래는 미분류로 둔다.

저장된 규칙은 새 Import Preview에만 카테고리를 채운다. 사용자는 저장 전에 모든 카테고리를 변경할 수 있고, “이 설명에 앞으로 적용”을 별도로 체크한 경우에만 해당 규칙을 생성 또는 교체한다. 규칙은 선택된 Import 후보와 같은 IndexedDB 트랜잭션으로 저장한다. 이전 Transaction은 수정하지 않는다.

## Consequences

- 규칙이 명시적 동의에서만 생겨 설명 가능한 자동 분류를 유지한다.
- 신뢰할 수 있는 상호 필드가 없는 한, 규칙은 실제 상호가 아닌 거래 설명의 정확 일치에 한정된다.
- IndexedDB v2에 `categoryRules` 저장소가 추가되지만 원본 파일·행·파일명은 저장하지 않는다.
- 규칙 관리 화면, 사용자 정의 카테고리, 퍼지 매칭, AI 제안과 과거 거래 일괄 재분류는 후속 단계다.

## Alternatives considered

- Import 시 자동 추론 카테고리: 확인 가능한 근거와 사용자 동의가 없어 채택하지 않았다.
- 기존 거래까지 규칙으로 갱신: 과거 원장을 예상치 못하게 바꾸므로 채택하지 않았다.
- 설명 대신 결제수단 또는 금액을 규칙 키로 사용: 동일 상호 재사용과 관계가 약하고 오분류 위험이 커 채택하지 않았다.
