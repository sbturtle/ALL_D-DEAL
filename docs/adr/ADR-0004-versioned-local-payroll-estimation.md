# ADR-0004 버전 지정 로컬 급여 추정 정책 채택

- 날짜: 2026-08-05
- 관련 결정: [ADR-0002 local-first](ADR-0002-local-first-architecture.md)

## 상태

Accepted

## 최초 사용자 요구

세전 연봉 또는 월급과 상여금을 입력하면 예상 실수령액에 반영되는 간단한 계산기를 Phase 1에 추가한다.

## 이후 확인된 문제

- 대한민국 근로소득 원천징수는 하나의 고정 세율이 아니라 간이세액표, 공제대상 가족 수, 자녀 수와 선택한 원천징수 비율을 사용한다.
- 국민연금·건강보험·장기요양보험·고용보험의 요율과 상·하한은 시점에 따라 달라진다.
- 상여 지급월의 정확한 세액은 지급대상기간과 기납부세액이 추가로 필요하다.
- 외부 계산 API를 런타임에 호출하면 local-first 원칙과 오프라인 가용성이 약해진다.

## 변경된 요구사항

Phase 1은 2026년 일반 직장근로자의 연간·월평균 실수령액을 추정한다. 연간 상여금은 12개월로 나눠 월평균 과세급여에 반영하고, 지급월별 실제 세액을 확정한다고 주장하지 않는다.

## 결정

공식 자료에서 확인한 간이세액표와 사회보험 기준을 버전이 있는 불변 정책 데이터로 저장하고 순수 계산 함수에 주입한다. 계산은 브라우저 안에서만 실행하며 결과에 정책 ID, 기준일과 한계를 표시한다.

계산 결과는 `PayrollEstimateResult`이며 Transaction이 아니다. 사용자가 입력한 값과 결과는 Phase 1에서 영속화하지 않는다.

## 결정 이유

- 같은 입력과 정책 버전에 대해 재현 가능한 결과를 제공한다.
- 급여 정보를 외부 서비스에 전송하지 않는다.
- 정책 변경이 UI와 계산 함수 곳곳의 magic number 수정으로 번지지 않는다.
- 실제 장부 수입과 계획용 추정값의 의미를 분리한다.

## 고려한 대안

### 런타임에 외부 급여 계산 API 호출

최신 규칙을 위임할 수 있지만 개인정보 전송, 네트워크 의존성과 서비스 변경 위험이 생긴다.

### 소득세를 고정 비율로 근사

구현은 작지만 가족 수와 누진 구조를 반영하지 못해 실수령액 계산기로서 오차가 크다.

### 전체 급여·세무 엔진 구현

정확한 상여, 연말정산과 예외를 다룰 수 있지만 Phase 1의 간단한 추정 범위를 크게 넘는다.

## 장점

- 오프라인에서도 계산 가능하고 입력이 사용자 기기를 떠나지 않는다.
- 공식 대표값과 정책 경계값을 자동 테스트할 수 있다.
- 향후 정책 파일을 추가해 연도별 갱신 경계를 명확히 할 수 있다.

## 단점

- 정책 변경 시 공식 자료를 다시 확인하고 데이터와 테스트를 갱신해야 한다.
- 회사의 보험 보수 산정, 감면·가입 제외와 상여 원천징수 방식에 따라 실제 급여명세서와 차이가 날 수 있다.
- 연간 상여를 월평균으로 나누므로 지급월의 현금흐름을 보여주지 않는다.

## 정책 근거와 검증 기준

- 근로소득세: 2026-03-01 시행 소득세법 시행령 별표 2 근로소득 간이세액표
- 국민연금: 2026년 근로자 부담률과 2026-07-01 적용 기준소득월액 상·하한
- 건강보험·장기요양보험: 2026년 직장가입자 보험료율과 보험료 상·하한
- 고용보험: 일반 근로자 실업급여 근로자 부담률

정책 데이터에는 출처 URL을 함께 두고, 표의 시작·끝 구간, 1천만원 경계, 공식 예시와 자녀 차감 사례를 테스트한다.

## 향후 다시 검토할 조건

- 사용자가 상여 지급월별 실수령액이나 정확한 법정 상여 원천징수를 요구한다.
- 개인별 보험 가입 제외·감면, 회사별 공제 또는 연말정산 결과를 반영해야 한다.
- 2026년 이후 정책을 지원하거나 여러 연도 시나리오 비교가 필요하다.
- Phase 6에서 실제 `INCOME` 거래와 추정값 비교 기능을 계획한다.
