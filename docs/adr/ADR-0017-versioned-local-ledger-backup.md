# ADR-0017 — 로컬 장부 백업을 버전 JSON으로 내보내고 원자적으로 복원한다

- 상태: 채택
- 날짜: 2026-10-01
- 관련: [ADR-0002](ADR-0002-local-first-architecture.md), [로컬 거래 저장 계약](../architecture/local-transaction-storage.md)

## 최초 사용자 요구

사용자는 이 브라우저에 저장한 장부를 다른 브라우저에서도 복구할 수 있도록 파일로 내보내고 다시 불러오고 싶어 한다.

## 이후 확인된 문제

로컬 저장소에는 거래 외에도 Import 이력, 공동결제 정산, 카테고리 규칙, 사용자 설정, 돈의 목적, 사용자 카테고리와 거래 이미지가 나뉘어 저장되어 있다. 거래만 복사하면 참조가 끊기고, 파일을 곧바로 적용하면 검증되지 않은 JSON이 현재 장부를 손상시킬 수 있다.

## 변경된 요구사항

- Settings에서 로컬 장부 전체를 내보내고 버전이 있는 백업을 복원한다.
- 복원 전에 실제 저장 레코드 건수와 교체 범위를 보여 주고 사용자의 별도 확인을 받는다.
- 구조와 참조 관계가 잘못되었거나 저장이 실패하면 현재 장부를 바꾸지 않는다.
- 원본 금융 파일과 원격 처리 데이터는 백업 대상에서 제외한다.

## 결정

1. 백업은 `ALL_D_DEAL_LOCAL_LEDGER` 포맷 ID, 정수 버전, UTC `exportedAt`, 저장소별 레코드가 든 `data`를 가진 JSON 버전 1로 고정한다.
2. 거래, Import 이력, 공동결제 정산, 정확·키워드 카테고리 규칙, 월 생활비 목표, 돈의 목적, 사용자 카테고리와 거래 이미지 첨부를 포함한다.
3. 원본 XLS·원본 행·Preview 후보·분석 trace·급여 계산 입력과 결과·Kakao 응답은 포함하지 않는다.
4. 가져온 JSON은 루트와 각 Domain 레코드, 예상하지 않은 필드, 중복 키, 거래·Import Batch·정산·카테고리·돈의 목적·첨부 참조를 검증한다. 공동결제 정산에서 한 거래가 여러 정산에 연결된 경우도 거부한다.
5. 사용자가 확인한 뒤 모든 IndexedDB 저장소를 하나의 읽기·쓰기 트랜잭션에서 교체한다. IndexedDB 오류는 전체 트랜잭션을 중단해 기존 레코드를 보존한다.
6. 파일 생성과 읽기, 검증, 교체는 브라우저 안에서만 처리하며 서버 업로드나 자동 동기화를 추가하지 않는다.

## 결정 이유

명시적인 포맷 버전은 이후 모델 변화와 파일 호환성을 구분한다. 로컬 Domain 검증과 관계 검증은 형식상 유효하지만 현재 장부에서 사용할 수 없는 고아 참조를 막는다. 사용자 확인과 단일 IndexedDB 트랜잭션은 잘못된 파일이나 저장 실패로 현재 장부가 부분 교체되는 일을 막는다.

## 고려한 대안

1. 원본 파일을 다시 파싱해 복구: 금융기관별 Parser 지원 범위에 종속되고 이미 정리한 카테고리·메모·정산·설정을 복구하지 못하므로 제외한다.
2. 서버 동기화나 클라우드 백업: 금융 데이터를 외부로 전송하는 경계를 새로 만들기 때문에 local-first 원칙에 맞지 않는다.
3. 기존 장부와 병합: 충돌 해결·중복 판정 정책이 필요하므로, 현재는 사용자가 선택한 백업으로 전체 장부를 교체한다.

## 장점과 단점

- 장점: 브라우저 사이에 로컬 장부와 참조 관계를 옮길 수 있고, 원본 금융 파일이나 외부 서버를 요구하지 않는다.
- 단점: 사용자가 JSON 파일을 직접 안전한 위치에 보관해야 한다. 거래 이미지 첨부도 JSON 크기에 포함된다.

## 향후 다시 검토할 조건

백업 데이터 크기로 브라우저 메모리 한도를 넘거나 암호화·부분 복원·병합 요구가 확인되면 별도 포맷 버전과 복구 계약을 정한다. 과거 버전 백업을 계속 지원해야 하는 요구가 생기면 버전별 변환 절차를 추가한다.
