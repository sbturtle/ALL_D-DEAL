# Requirements History

현재 요구사항 자체는 [requirements.md](requirements.md)를 기준으로 하며, 이 문서는 변경 전후와 결정 이유를 시간순으로 보존한다.

## 2026-08-05 — 금융 API 자동 연동에서 파일 Import로 전환

### 최초 요구

금융기관 API로 사용자의 계좌·카드 소비내역을 자동 조회해 가계부를 만든다.

### 확인된 문제

대한민국에서 개인 개발자가 자신의 금융 데이터를 공식 API로 자유롭게 연동하기 어렵다는 제약을 프로젝트 전제로 확인했다.

### 변경

사용자가 MyData/MyPDS 또는 금융기관에서 직접 내려받은 PDF, CSV, XLSX를 가져와 파싱·분류하는 흐름으로 바꾼다.

### 변경 이유

사용자가 데이터에 대한 통제권을 유지하면서 현실적으로 구현 가능한 경로이기 때문이다.

### 현재 결정

파일 Import를 우선 개발하며, 실제 금융 형식은 마스킹된 샘플이 확보된 뒤 Adapter 단위로 지원한다. 자세한 내용은 [ADR-0001](../adr/ADR-0001-file-import-over-financial-api.md)을 따른다.

## 2026-08-05 — 실시간 동기화에서 주 1회 정리로 전환

### 최초 요구

금융 거래를 자동으로 지속 수집한다.

### 확인된 문제

사용자에게 실시간 반영은 핵심 가치가 아니며 주말에 일주일치 내역을 정리하면 충분하다.

### 변경

실시간 수집 대신 사용자가 주 1회 실행하는 Import·검토 흐름을 최적화한다.

### 변경 이유

불필요한 인증·서버·동기화 복잡도를 줄이고 실제 사용 습관에 맞추기 위해서다.

### 현재 결정

백그라운드 동기화 없이 수동 파일 Import를 기본으로 한다. 자세한 내용은 [ADR-0003](../adr/ADR-0003-weekly-import-instead-of-realtime.md)을 따른다.

## 2026-08-05 — local-first를 초기 기본 구조로 채택

### 최초 요구

웹으로 먼저 개발하고 향후 Galaxy Android 환경으로 확장한다.

### 확인된 문제

금융 데이터는 민감하며 현재 범위에는 외부 공유나 다중 기기 동기화 요구가 없다.

### 변경

브라우저 내부 처리와 IndexedDB 저장을 우선하고 백엔드는 만들지 않는다.

### 변경 이유

데이터 노출 면적과 초기 복잡도를 줄이면서 핵심 Import 흐름을 검증할 수 있기 때문이다.

### 현재 결정

초기 데이터 경계는 사용자 기기 내부다. 자세한 내용은 [ADR-0002](../adr/ADR-0002-local-first-architecture.md)을 따른다.

## 2026-08-05 — 기능 단위 로컬 커밋 규칙 추가

### 추가 요구

구현 과정에서 로컬 커밋을 필수로 수행하고, 변경을 기능 단위로 나눈다.

### 형식

```text
[Type] : 커밋 제목

커밋메시지 본문
```

### 현재 결정

Phase와 무관하게 서로 독립적으로 설명 가능한 변경을 분리해 커밋한다. 커밋 본문에는 변경 이유와 범위를 기록하며, 별도 요청 없이 push하지 않는다.

## 2026-08-05 — Phase 1 급여 실수령 추정기 추가

### 추가 요구

다음 작업에 앞서 세전 연봉 또는 월급과 상여금을 입력해 예상 실수령액을 확인할 수 있는 간단한 계산기를 만든다.

### 확인된 제약

- 근로소득 원천징수는 고정 세율이 아니라 과세 월급여, 공제대상 가족 수와 자녀 수에 따른 간이세액표를 사용한다.
- 상여의 실제 원천징수액은 지급대상기간, 이전 급여와 이미 납부한 세액에 따라 달라져 연간 상여 총액만으로 지급월 실수령액을 확정할 수 없다.
- 계산 결과를 실제 `INCOME` 거래로 만들면 이후 Import 기반 장부와 예상값이 섞인다.

### 변경

Phase 1을 Web Skeleton `1A`와 급여 실수령 추정기 `1B`로 나눈다. 사용자는 연봉·월급 입력 모드, 별도 연간 상여금, 월 비과세액, 공제대상 가족·자녀 수와 원천징수 비율을 입력한다. 상여금은 12개월 월평균으로 반영한다.

### 현재 결정

- 공식 근거와 기준일을 가진 2026년 계산 정책을 브라우저에서 로컬로 실행한다.
- 결과는 연간·월평균 예상액이며 공식 급여명세서나 세무 결과로 표현하지 않는다.
- Phase 1 입력과 결과는 메모리에만 두고 저장·URL 반영·거래 생성을 하지 않는다.
- Phase 6에서 실제 Import된 `INCOME`과 예상값을 비교할 수 있지만 자동 합산하거나 대체하지 않는다.
- 개인별 기본값 저장, 연말정산, 상여 지급월별 법정 원천징수와 여러 연도 비교는 별도 후속 요구가 확인된 뒤 계획한다.

자세한 계산 경계와 정책 갱신 방식은 [ADR-0004](../adr/ADR-0004-versioned-local-payroll-estimation.md)를 따른다.
