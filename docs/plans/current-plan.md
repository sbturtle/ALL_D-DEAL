## 목표

확인할 수 있게 한다.

## 범위

2. 가맹점 정규화값을 우선하고 없으면 원본 가맹점·거래 설명을 사용해 같은

   지출 요약에서도 제외해 금액을 중복 표시하지 않는다.

   기존 요약·편집 흐름은 변경하지 않는다.

## 완료 조건

3. 반복 지출이 없거나 거래가 비어 있으면 해당 카드를 표시하지 않는다.
4. 관련 테스트, lint, typecheck, build가 통과하고, 브라우저 실행 환경이 있으면

# 10B단계 — 거래별 자금통과 자금통별 지출 집계

- 상태: `DONE`
- 계획 갱신일: 2026-08-13
- 선행 단계: 10A단계 다대다 공동결제 정산 `DONE`

## 목표

지출 카테고리와 별개로 거래가 어느 자금 목적에 속하는지 나타내는 `BudgetBucket`을 도입한다. 기본 자금통별 지출을 안전하게 집계하고, 기존 생활비는 `LIVING` 자금통의 지출만 뜻하도록 바꾼다.

## 범위와 결정

1. `BudgetBucket`은 카테고리와 별도 Domain·IndexedDB 모델이다. 초기 기본값은 `LIVING`, `IRREGULAR`, `EMERGENCY`, `SAVING`, `HOUSING_MARRIAGE`, `INVESTMENT`, `OTHER`이며, 이후 사용자 정의 자금통을 저장할 수 있도록 문자열 ID와 `budgetBuckets` 저장소를 사용한다.
2. 이번 MVP는 Transaction 하나에 필수 `budgetBucketId` 하나만 저장한다. `TransactionAllocation[]` 금액 분할, 자금통 관리 화면·예산 목표 관리와 자동 Merchant 규칙은 후속 단계로 남긴다.
3. 새 Import 후보와 기존 Transaction은 기본값 `LIVING`을 가진다. 사용자는 저장된 거래의 편집 시트에서 카테고리와 독립적으로 자금통을 바꿀 수 있으며, 수입에도 같은 단일 필드를 둬 향후 수입 배분을 막지 않는다.
4. IndexedDB v6 업그레이드는 자금통이 없는 기존 모든 Transaction과 기존 공동결제 정산에 `LIVING`을 넣고, 기본 자금통 7개를 seed한다. 데이터의 실제 목적을 단정하지 않는 legacy 기본값임을 UI·문서에 고지한다.
5. 자금통별 집계는 일반 지출을 별도로 계산하고, 기존 생활비 카드·목표·주간 그래프는 `LIVING`만 사용한다. 다대다 공동결제에는 별도 `budgetBucketId`를 두어 순지출을 사용자가 선택한 하나의 자금통에 귀속하며, 정산금의 자동 분할 배분은 하지 않는다.
6. Home에는 대규모 재설계 대신 자금통별 지출의 작은 요약 목록을 추가한다. Import Preview는 기본 자금통을 표시하되, Preview별 변경 UI는 후속 단계로 남긴다.

## 완료 조건

1. 카테고리와 자금통은 별도 타입·검증·표현을 갖는다.
2. Transaction과 공동결제 정산마다 `budgetBucketId`를 저장·검증하고 기존 데이터는 v6에서 안전하게 읽힌다.
3. 기본 지출은 `LIVING`으로 추천되지만 편집 시트에서 `IRREGULAR`, `EMERGENCY` 등으로 변경할 수 있다.
4. 예시의 카페·식사·축의금·병원비는 전체 소비와 생활비·비정기비·비상금이 각각 올바르게 집계된다.
5. Home의 생활비 표시는 모든 지출이 아니라 `LIVING` 자금통만 사용하며, 자금통별 작은 요약을 확인할 수 있다.
6. 관련 요구사항, ADR, 아키텍처·데이터 모델, 엔지니어링 로그를 한국어로 갱신하고 기능 단위 커밋과 검증 결과를 남긴다.

# 현재 작업 — 거래 등록·분류·목록 UX 통합

- 상태: `IN_PROGRESS`
- 계획 갱신일: 2026-08-29
- 작업 유형: 거래 등록·분류·목록 UI/저장 수직 슬라이스

## 목표

거래를 파일을 끌어 놓는 방식으로 쉽게 등록하고, 등록·편집 과정에서
카테고리와 메모·목적을 한 번에 관리한다. 거래 목록은 목적과 카테고리
기준으로 빠르게 좁히고, 여러 거래를 선택해 일괄 분류할 수 있게 한다.
공동결제 정산은 거래 목록 아래에 펼쳐 두지 않고 별도 작업 공간으로
분리하며, 거래별 이미지는 로컬 브라우저에만 저장한다.

## 범위

1. 기존 XLS Parser와 동일한 경로를 사용하는 접근 가능한 드래그앤드롭
   업로드 영역을 Import 화면에 추가한다.
2. Import Preview와 거래 상세 편집에서 카테고리·메모·목적을 함께 바꾸고,
   카테고리 선택창 안에서 사용자 카테고리를 추가한다.
3. 사용자 카테고리와 거래 이미지 첨부를 IndexedDB에 로컬 전용으로 저장한다.
4. 거래 목록에 목적 탭과 목적 내 카테고리 필터를 제공하고 다중 선택
   거래의 카테고리·목적을 한 번에 변경한다.
5. 공동결제 정산을 별도 탭으로 이동하고 거래 상세와 연결 상태를 명확히
   보여 준다.
6. 기존 저장 데이터·기본 카테고리·기본 목적과 모바일 접근성 동작을
   보존하면서 현재 디자인 토큰으로 화면 계층과 상태를 다듬는다.

## 완료 조건

1. `.xls` 파일을 클릭 선택하거나 드래그앤드롭하면 동일한 Preview가 열리고,
   잘못된 확장자·크기·읽기 오류가 기존 오류 상태로 표시된다.
2. Preview와 거래 상세에서 카테고리·메모·목적을 저장할 수 있고, 새
   카테고리를 선택창에서 추가한 뒤 즉시 선택할 수 있다.
3. 거래 상세에서 이미지를 추가·교체·삭제할 수 있으며 이미지 원본은
   서버나 거래 목록 텍스트에 노출되지 않는다.
4. 목적 탭과 카테고리 필터가 함께 동작하고, 선택 거래의 일괄 카테고리·
   목적 변경이 한 번의 저장으로 반영된다.
5. 공동결제 정산 UI가 거래 목록 하단에 고정 노출되지 않고 별도 탭에서
   생성·해제되며, 연결된 거래에서 상태를 확인할 수 있다.
6. 관련 테스트, lint, typecheck, test, build와 360px·768px·1280px
   실제 브라우저 흐름 검증이 통과한다.
