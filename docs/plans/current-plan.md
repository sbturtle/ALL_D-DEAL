# 10A단계 — 다대다 공동결제 정산

- 상태: `DONE`
- 계획 갱신일: 2026-08-10
- 선행 단계: 9B단계 완료 계획 문서 한국어 정리 `DONE`

## 목표

공동결제 정산 하나에 여러 지출과 여러 수입을 연결할 수 있도록 계약, 저장소, 생활비 집계, 화면을 함께 확장한다. 원본 거래와 일반 수입·지출 합계는 보존하고, 생활비 목표에는 연결된 묶음의 순지출만 반영한다.

## 범위와 결정

1. `BudgetSettlement`를 `outflowTransactionIds`와 `inflowTransactionIds` 배열을 가진 모델로 변경한다. 두 배열은 모두 하나 이상이며 각각 중복이 없고, 한 거래는 최대 하나의 정산에만 연결한다.
2. 이전 스키마의 단일 `payerOutflowTransactionId`와 `reimbursementInflowTransactionIds`는 IndexedDB 버전 5에서 배열 모델로 자동 변환한다.
3. 생활비 집계는 선택 기간 안의 연결 지출 합계에서 연결 수입 전체를 차감하고 0보다 작아지지 않게 한다. 연결 수입 날짜가 이후여도 연결 지출 기간에 귀속한다.
4. 공동결제 화면은 지출·수입을 각각 다중 선택 목록으로 제공하고, 선택된 건수와 순지출 미리보기를 보여 준다.
5. 도메인·애플리케이션·저장소·UI를 기능 단위로 검증하고, 관련 요구사항·ADR·저장 계약·엔지니어링 로그를 한국어로 갱신한다.

## 완료 조건

1. 다대다 모델 검증이 배열 필수·중복·UUID·예상하지 못한 필드를 검사한다.
2. 저장 유스케이스가 여러 지출은 `OUTFLOW`, 여러 수입은 `INFLOW`인지 확인하고 중복 연결을 거부한다.
3. 기존 v4 데이터가 새 스키마로 읽히며 새 데이터가 배열 모델로 저장된다.
4. 생활비 집계와 화면에서 2개 이상 지출·수입을 연결하고 해제할 수 있다.
5. 가능한 lint, typecheck, test, build와 `git diff --check` 결과를 기록하고 기능 단위 커밋을 남긴다.

### 슬라이스 2 — IndexedDB 저장과 마이그레이션

- 새 저장·조회와 업그레이드 테스트를 추가한다.
